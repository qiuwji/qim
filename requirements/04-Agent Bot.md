# 04-Agent Bot

## 一、需求背景

QIM 当前仅支持用户间沟通，缺少智能助手来帮助用户处理信息、执行任务。新增 Agent Bot 功能，每个用户拥有一个专属 Bot 账号（均由平台统一的 Agent 服务驱动）。Bot 的核心定位是帮助用户解决问题——根据被授予的权限，访问聊天记录等数据，完成搜索消息、总结会话等任务。

## 二、目标用户

所有 QIM 注册用户。

## 三、核心场景

- 用户需要对某个会话进行总结，让 Bot 提取要点
- 用户忘记了某条历史消息，让 Bot 搜索并定位
- 用户需要定时提醒，让 Bot 在指定时间推送通知
- 用户在 Bot 对话中新建会话，清除上下文重新开始
- Bot 在对话中主动识别用户需求，询问是否需要帮助
- Bot 服务异常时，用户收到明确的错误提示

## 四、功能范围

### 4.1 Bot 生命周期

| 功能 | 说明 | 验收标准 |
|------|------|---------|
| 激活 Bot | 用户首次激活 Bot | Bot 出现在聊天列表和好友列表的 Bot 分组中 |
| 新建会话 | 用户新建一个与 Bot 的对话，上下文从零开始 | 新会话独立于旧会话，旧会话保留在会话列表中可随时切回 |

每个用户仅能拥有一个 Bot。

### 4.2 基础对话能力

Bot 与用户通过对话交互，无论是否授予权限，均具备以下能力：

| 功能 | 说明 | 验收标准 |
|------|------|---------|
| 私聊对话 | 用户在聊天列表或好友列表点击 Bot 进入私聊 | 支持多轮对话，Bot 理解并响应用户指令 |
| 通用能力 | 总结会话、搜索消息、定时提醒、主动询问等 | 无需用户配置，开箱即用 |

Bot 使用系统默认配置（默认昵称、默认头像），一期不开放用户自定义。

### 4.3 异常处理

| 场景 | 表现 |
|------|------|
| LLM 服务不可用 | Bot 回复"服务暂时不可用，请稍后再试" |
| LLM 响应超时 | Bot 回复"响应超时，请稍后再试" |
| 用户指令无法理解 | Bot 回复"抱歉，我没有理解您的意思，可以换个说法吗" |

### 4.4 权限

用户可以给 Bot 授予权限，Bot 获得权限后才能访问对应维度的数据。不授予权限时，Bot 仅具备基础对话能力。

权限采用**全量授权**模式：用户授予某个权限后，Bot 即可访问该维度下的全部数据，无需逐项选择。例如授予「查看好友列表」后，Bot 可查看所有好友信息。

权限授予由用户决定，授予哪些、何时授予，用户自主控制。

| 权限 | 说明 | 验收标准 |
|------|------|---------|
| 查看好友列表 | Bot 可读取用户的好友信息 | 用户问"我的好友有哪些"，Bot 能列出 |
| 查看好友会话 | Bot 可读取用户与好友的私聊会话记录 | 用户问"我和张三最近聊了什么"，Bot 能回答 |
| 查看群聊信息 | Bot 通过用户身份读取用户所在群聊的基本信息 | 用户问"XX群有哪些人"，Bot 能列出成员 |
| 查看聊天记录 | Bot 可读取会话的历史消息（含文件记录） | 用户问"上周五发了什么文件"，Bot 能检索并回答 |

Bot 在对话中根据用户指令自行判断需要查询哪个会话。

权限列表可扩展。Bot 的权限上限不超过创建者自身的权限。权限变更即时生效。

## 五、用户流程

### 5.1 入口

- **新注册用户**：聊天列表中默认显示 Bot 会话入口
- **已有用户**：激活 Bot 后，Bot 出现在好友列表的专门 Bot 分组中，同时出现在聊天列表

### 5.2 激活 Bot

```
用户点击"激活 AI Bot"
  → Bot 账号创建
  → Bot 出现在聊天列表和好友列表 Bot 分组中，使用默认头像和默认昵称
```

### 5.3 私聊对话

```
用户打开 Bot 会话 → 发消息 → Bot 回复
```

### 5.4 新建会话

```
用户在 Bot 对话界面点击"新建会话"
  → 开启空白对话，上下文清空
  → 旧会话保留在会话列表中
```

### 5.5 授予权限

```
用户进入 Bot 资料页 → 权限设置 → 选择要授予的权限 → 保存
Bot 获得对应数据访问能力，即时生效
```

## 六、交互规格

### 6.1 Bot 入口

- 新注册用户：聊天列表中出现 Bot 入口
- 已有用户激活后：好友列表中设专门 Bot 分组展示，聊天列表中同步出现
- Bot 始终显示为在线

### 6.2 对话体验

- Bot 回复时显示"正在输入…"状态
- Bot 可主动询问用户是否需要帮助

### 6.3 权限面板

- 入口：Bot 资料页
- 权限以列表形式展示，逐项开关
- 变更即时生效

### 6.4 权限撤回后

- 用户撤回某个权限后，Bot 在当前及后续对话中不能再访问该维度数据
- 若正在进行中的依赖该权限的操作，Bot 回复"该操作需要 XX 权限，请重新授权"

## 七、业务规则

1. 每个用户最多一个 Bot
2. Bot 私聊中响应所有消息
3. Bot 权限不超过创建者自身权限
4. Bot 权限采用全量授权，授予即对该维度全部数据生效
5. Bot 不能被其他用户添加为好友
6. Bot 不参与音视频通话
7. Bot 自己的消息不触发自身再次回复
8. 权限变更即时生效，撤回后 Bot 不可再访问对应数据

## 八、不做的事

- 删除 Bot
- 多 Bot 支持
- 用户自定义 Bot 昵称/头像/风格设定
- Bot 加入群聊作为成员参与对话
- Bot 主动推送消息（定时日报等）
- Bot 跨用户共享
- 语音/图片多模态
- 用户自行部署/启动 Agent 进程（Agent 由平台统一托管）

## 九、风险

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| LLM 服务不可用 | 中 | Bot 无响应 | 返回明确错误提示，不阻塞 |
| LLM 响应超时 | 中 | 用户等待过长 | 设超时时间，超时返回提示 |
| Bot 回答质量差 | 中 | 用户不信任 | 默认 prompt 调优 |
| Bot 被滥用发送违规内容 | 低 | 安全风险 | 内容安全过滤 |
| 权限过宽导致隐私泄露 | 低 | 隐私风险 | 权限默认关闭，用户主动授予 |
