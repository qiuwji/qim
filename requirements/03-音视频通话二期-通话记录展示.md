# 音视频通话二期：通话记录展示

## 一、需求背景

一期已实现 1对1 语音/视频通话的实时信令与控制（发起、接听、拒绝、挂断），通话结束后已将通话记录（通话双方、类型、时长、结束原因）持久化到 `Call` 表。但当前消息列表无法展示这些通话记录，用户无法在聊天记录中回溯通话历史。

本期将通话记录作为一种系统消息类型接入消息体系，使通话记录与文字、图片消息在同一消息流中按时间序展示。

## 二、目标用户

所有 QIM 注册用户。

## 三、核心场景

- 用户与对方通话结束后，在聊天记录中看到一条通话记录卡片，展示通话类型和时长
- 用户翻看历史消息时，能看到过去的通话记录（区分"已接通"与"未接通"）
- 用户从消息列表拉取历史消息时，通话记录与普通消息混合返回

## 四、功能范围

### 4.1 通话记录落消息

| 功能 | 说明 | 验收标准 |
|------|------|---------|
| 通话结束自动生成消息 | CallActor OnStop 写入通话记录时，同步往 Conversation 写入一条系统消息 | 通话结束后消息列表出现对应记录 |
| 语音通话记录 | 语音通话结束后生成 call_type=1 的记录 | 展示"语音通话"及通话时长 |
| 视频通话记录 | 视频通话结束后生成 call_type=2 的记录 | 展示"视频通话"及通话时长 |
| 未接通记录 | 拒绝/超时/取消 也生成记录 | 展示对应结束原因（已拒绝/已取消/无人接听） |

### 4.2 消息拉取

| 功能 | 说明 | 验收标准 |
|------|------|---------|
| 历史消息包含通话记录 | `msg/list`、HTTP 历史消息接口返回的消息列表中包含通话记录 | 拉取消息时能获取到通话记录 |
| 消息搜索不包含通话记录 | 通话记录不参与关键词搜索 | 搜索"通话"不返回通话记录 |

### 4.3 消息推送

| 功能 | 说明 | 验收标准 |
|------|------|---------|
| 通话记录实时推送 | 与普通新消息一样走 `message/new` 推送 | 在线用户能实时收到通话记录 |

### 4.4 会话列表摘要

| 功能 | 说明 | 验收标准 |
|------|------|---------|
| 最后一条消息摘要 | 若最后一条消息是通话记录，会话列表展示对应的摘要文本 | 如"[语音通话] 05:30"、"[视频通话] 已拒绝" |

## 五、用户流程

```
任一方挂断 / 拒绝 / 超时 / 取消
  → CallActor.OnStop
    → 写入 Call 表（一期已有）
    → 往 Conversation 写入一条系统消息（新增）
      → msg_type = 新系统消息类型
      → content = JSON（call_id, call_type, duration, end_reason）
    → 发布 MessageSentEvent（走现有消息推送链路）
  → 双方消息列表出现通话记录卡片
```

## 六、交互规格

### 6.1 消息列表展示

通话记录在消息流中以**卡片**形式展示，与普通消息气泡区分：

| 状态 | 展示内容 | 样式 |
|------|---------|------|
| 语音通话 - 已接通 | "语音通话" + 通话时长（MM:SS） | 简化卡片，电话图标 |
| 视频通话 - 已接通 | "视频通话" + 通话时长（MM:SS） | 简化卡片，视频图标 |
| 语音通话 - 未接通 | "语音通话" + 结束原因（已拒绝/已取消/无人接听） | 简化卡片，电话图标（灰色） |
| 视频通话 - 未接通 | "视频通话" + 结束原因 | 简化卡片，视频图标（灰色） |

### 6.2 会话列表摘要

- 已接通：`[语音通话] 02:30` / `[视频通话] 05:00`
- 已拒绝/已取消：`[语音通话] 已拒绝`
- 超时：`[语音通话] 无人接听`

## 七、业务规则

1. 通话记录作为系统消息（msg_type 为新分配值），与普通消息混合存储、按 seq 排序
2. 通话记录不可撤回、不可回复、不可转发
3. 通话记录不可编辑
4. 通话记录不参与关键词搜索
5. 通话记录的 `content` 存储结构化 JSON，前端负责渲染
6. 通话已接通才展示时长，未接通展示结束原因文本
7. 通话记录与一期 Call 表记录一一对应（通过 call_id 关联）

## 八、不做的事

- 通话记录不支持点击回拨（三期考虑）
- 群聊通话记录（三期群组音视频通话后跟进）
- 通话记录的客户端本地删除功能（复用现有普通消息的本地删除机制即可）
- 通话记录的屏幕共享/录制标记

## 九、与一期的关系

| 一期 | 二期 |
|------|------|
| CallActor.OnStop 写 Call 表 | 追加写入 Conversation 系统消息 |
| 通话记录仅在 DB 存储 | 接入消息体系，在消息列表展示 |
| 前端实时 overlay 通知 | 前端消息列表卡片展示 |
